# Shift Sync セットアップガイド

スマホから希望の出勤時間をタップで送信し、管理者は自動転記された希望を調整するだけの
シンプルなシフト希望収集システムです。

## 2つのモード

| モード | 設定 | データの保存先 | 用途 |
|---|---|---|---|
| **デモモード**(初期状態) | 不要 | ブラウザ内(localStorage) | 操作感の確認。**端末間でデータは共有されません** |
| **本番モード** | 下記の手順(10分程度) | Google スプレッドシート | 実運用。従業員のスマホ→管理者の画面へデータが届く |

デモモードは何も設定せずに動きます。初回はサンプルの従業員と希望データが自動投入されるので、
`shift/index.html`(従業員画面)と `shift/admin.html`(管理者画面)を同じブラウザで
行き来すれば一連の流れを確認できます。

---

## 本番モードのセットアップ(Google スプレッドシート + Apps Script)

必要なもの: Googleアカウントのみ。サーバーやデータベースの契約は不要です。

### 1. スプレッドシートを作成

1. [Google スプレッドシート](https://sheets.google.com) で新規スプレッドシートを作成
2. 名前は自由(例:「シフト管理データ」)。シートの中身は空でOK(初回アクセス時に自動作成されます)

### 2. Apps Script にコードを貼り付け

1. スプレッドシートのメニュー「**拡張機能 → Apps Script**」を開く
2. エディタに最初から入っているコードを全て消し、`shift/gas/Code.gs` の内容を丸ごと貼り付けて保存(💾)

### 3. 管理者トークンを設定

1. Apps Script エディタ左側の歯車「**プロジェクトの設定**」を開く
2. 下の方の「**スクリプト プロパティ**」→「スクリプト プロパティを追加」
3. プロパティ名: `ADMIN_TOKEN` / 値: 好きな長い文字列(例: `mystore-2026-xk29fj`)
   - このトークンを知っている人だけがシフトの確定・従業員の追加削除をできます
   - **コードやリポジトリには書かないでください**

### 4. ウェブアプリとしてデプロイ

1. エディタ右上「**デプロイ → 新しいデプロイ**」
2. 歯車アイコン →「**ウェブアプリ**」を選択
3. 設定:
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**(※従業員がログインなしで送信するために必要)
4. 「デプロイ」→ Googleアカウントへのアクセスを承認
   (「このアプリは確認されていません」と出たら「詳細 → 安全でないページに移動」で続行。
   自分で作ったスクリプトなので問題ありません)
5. 表示された **ウェブアプリのURL**(`https://script.google.com/macros/s/…/exec`)をコピー

### 5. URLをアプリに設定

`shift/js/config.js` を開き、コピーしたURLを設定します:

```js
GAS_URL: "https://script.google.com/macros/s/XXXX/exec",
```

あわせて施設名・時間帯ブロック(初期値は学童向けの「午前/午後/1日」)・必要人数なども
`config.js` で自由に変更できます。

### 6. 疎通確認

1. ブラウザでウェブアプリのURLを直接開く → `{"ok":true,"service":"shift-sync","version":1}` と表示されればOK
2. `shift/admin.html` を開く → 初回に管理者トークンの入力を求められるので、手順3で決めた値を入力
3. 「⚙ 従業員管理」から従業員を登録
4. `shift/index.html` をスマホで開いて希望を送信 → 管理画面に反映されれば完了
   (スプレッドシートに `Employees` などのシートが自動作成され、データが見えるようになります)

### 従業員への共有

従業員に共有するのは **`shift/index.html` のURLだけ**です(管理画面の共有モーダルからコピーできます)。
LINEグループ等に貼っておけば、各自がスマホで開いて名前をタップ→希望を送るだけになります。

## 管理者ページのPIN(任意)

従業員がうっかり管理画面を開いて操作してしまうのを防ぐ簡易PINを設定できます。

1. PIN(例: 4〜8桁の数字)を決める
2. そのSHA-256ハッシュを作る。macOS/Linuxのターミナルなら:
   ```bash
   printf '1234' | shasum -a 256
   ```
   (ブラウザの開発者コンソールでも `ShiftCore.sha256Hex("1234").then(console.log)` で取得できます)
3. `config.js` の `ADMIN_PIN_HASH` に貼り付ける

## ⚠ セキュリティ上の注意(必ず読んでください)

- このシステムは**静的サイト**です。`admin.html` はURLを知っていれば誰でも画面を開けます
- PINゲートは**誤操作防止**であり、セキュリティ保護ではありません(JSを読めば回避できます)
- 本当の防衛線は**GAS側の管理者トークン**です。トークンを知らない人は、画面を開けても
  シフトの確定・公開・従業員の追加削除はサーバー側で拒否されます
- ただし「全員の希望・確定シフトの**閲覧**」はトークンなしでも可能な設計です
  (従業員が確定シフトを見るため)。閲覧まで制限したい場合は、本格的な認証を持つ
  仕組みが必要で、本システムの範囲外です
- 個人情報は「名前(ニックネーム可)」以外保存しない運用を推奨します

## 運用のヒント

- 週の切り替わりは `config.js` の `WEEK_STARTS_ON`(初期値: 月曜)基準です
- 従業員の削除は「無効化」です(過去の週の表示を壊さないため)。誤って無効化しても
  管理画面から「有効化」で戻せます
- 想定規模は従業員20名程度まで。それを超える場合や過去データが数年分たまった場合は、
  スプレッドシートを年単位で作り直すのがシンプルです(古いシートはコピーして保管)
- コード(Code.gs)を修正した場合は「デプロイ → デプロイを管理 → 編集(鉛筆)→
  新バージョン」で**再デプロイが必要**です(URLは変わりません)

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 従業員画面で「読み込みに失敗」 | `GAS_URL` の貼り間違い/デプロイの「アクセスできるユーザー」が「全員」になっていない |
| 管理画面で「認証エラー」 | 入力したトークンがスクリプトプロパティ `ADMIN_TOKEN` と不一致。管理画面をリロードすると再入力できます |
| Code.gs を直したのに反映されない | 新バージョンでの再デプロイ忘れ(上記「運用のヒント」参照) |
| ブラウザのコンソールにCORSエラー | fetch の Content-Type が `text/plain` 以外になっている(改造した場合)。`application/json` はGASでは使えません |
| シートの時刻が `11:00` でなく変な日付になる | セルの書式が「自動」になっている。シート全体を選択 → 表示形式 → 数字 → 書式なしテキスト に戻す |
