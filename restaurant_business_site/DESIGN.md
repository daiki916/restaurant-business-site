# 品書き（SHINAGAKI）— サイト設計書

飲食店専門の「メニューデザイン ＋ 集客支援」スタジオのコーポレート／サービスサイト。
参考サイト **Be BLOOM（https://bebloom.co.jp/）** を構造・導線・雰囲気の分析対象として使用し、
コピーではなく「分析 → 再設計」でより成果につながるサイトを構築した。

> 【注記】参考サイトは自動取得（HTTP fetch）が 403 で拒否されたため、検索エンジンにインデックスされた
> 公開情報（トップ／会社概要／ブランド一覧／お問い合わせの各ページ構成、企業理念、事業内容）と、
> 同ジャンル（飲食企業コーポレートサイト）の一般的な設計パターンをもとに分析している。

---

## 1. 参考サイトの優れている点

| 項目 | 評価 |
| --- | --- |
| 情報設計 | 「事業（ブランド）／会社概要／採用／お問い合わせ」と、企業サイトに必要な要素だけに絞られている。迷子になりにくい |
| ブランド軸の明快さ | 「やろうぜ！九州！」という一言で、企業の立ち位置・世界観・採用ターゲットまで一気に伝わる。強いコピーが情報量の少なさを補っている |
| 事業の見せ方 | 複数の飲食ブランド（かこみ庵／あや鶏／八州など）を一覧化し、多店舗展開の実績＝信頼をビジュアルで示している |
| 写真の使い方 | 料理・店内・スタッフの写真を大きく使い、業種が数秒で伝わる。飲食業では正しい判断 |
| 地域性の訴求 | 「九州」というローカル軸を全面に出すことで、大手チェーンとの差別化と共感を同時に獲得している |
| 採用導線 | 採用サイトを別ドメインで分離し、企業情報と求職者向け情報を混在させていない |

## 2. 参考サイトの改善できる点（＝本サイトで上回るポイント）

| 課題 | 本サイトでの解決 |
| --- | --- |
| ファーストビューが「雰囲気」中心で、**具体的な価値が数字で示されていない** | ヒーロー直下に実績数値バー（制作数・平均客単価変化・継続率・初回相談無料）を配置し、数秒で判断材料を渡す |
| CTA が「お問い合わせ」の一種類のみ。**検討段階が浅いユーザーの受け皿がない** | CTA を2階層に設計。主CTA「無料相談」＋副CTA「料金を見る／制作事例を見る」。さらにモバイルは固定CTAバーで常時表示 |
| 「悩みへの共感」「選ばれる理由」といった**説得パートが弱い** | 課題共感 → 選ばれる理由 → サービス内容 → 実績 → 運営者 → FAQ → CTA という、意思決定順に沿ったストーリー構成 |
| 料金・進め方が公開されておらず、**問い合わせ前の不安が残る** | 料金プランを全公開。追加費用の有無、納期、支払い方法まで明記。5ステップの流れも図解 |
| FAQ が独立していない／少ない | 想定不安（費用・納期・遠方対応・印刷・解約）を FAQ 化。`<details>` によるネイティブアコーディオンで JS 不要・SEO 対応（FAQPage 構造化データ） |
| 装飾的な画像が多く、**表示速度に不利** | 写真ライブラリや外部アイコンフォントを使わず、オリジナル SVG ＋ CSS で構築。外部リクエストは Google Fonts のみ |
| アクセシビリティ配慮が読み取りにくい | スキップリンク、`aria-*`、フォーカスリング、キーボード操作、`prefers-reduced-motion`、コントラスト比 4.5:1 以上を全体で担保 |
| フォームの入力支援が薄い | リアルタイム検証・エラーメッセージ（`aria-live`）・送信完了パネル・`autocomplete` 属性を実装 |

## 3. 制作するサイトのコンセプト

- **サイト名**：品書き（SHINAGAKI）
- **業種・サービス**：飲食店専門の「メニューデザイン」＋「Web集客支援（MEO・SNS・写真）」
- **主なターゲット**：席数 10〜40 席規模の個人経営・小規模法人の飲食店オーナー（30〜50代）。
  デザイン会社に頼むほどの予算はないが、手書き／既製テンプレートのメニューに限界を感じている層。
- **サイトの目的**：無料相談（フォーム／LINE）への送客
- **最も伝えたい強み**：**「デザインを作って終わりにしない」**。
  原価と粗利から逆算して“売りたい一品が売れる”メニュー構成を設計し、
  公開後の反応まで数字で追いかける。
- **雰囲気**：和モダン／落ち着き／職人的な誠実さ。派手さより「任せて安心」
- **コンセプトコピー**：**一枚の品書きが、店の利益をつくる。**

## 4. 配色とフォントの提案

### カラーパレット

| 役割 | 色 | 値 | 意図 |
| --- | --- | --- | --- |
| ベース | 生成り | `#FBF8F3` | 紙のような温かさ。白より目が疲れない |
| ベース（副） | 淡砂 | `#F4EEE4` | セクションの区切りを罫線に頼らず作る |
| 文字 | 墨 | `#17140F` | 純黒を避けコントラストを保ちつつ柔らかく |
| メイン | 朱（しゅ） | `#B33A2B` | 食欲を刺激する赤系。ただし彩度を落として「安っぽい赤」を回避 |
| 深色 | 深緑（ふかみどり） | `#143A34` | CTA・フッターの背景。信頼感と高級感 |
| アクセント | 金茶 | `#B08D4F` | 見出しの装飾・数値の強調に少量だけ |

- 参考サイト系統の「暖色ど真ん中」ではなく、**朱 × 深緑**の二軸にすることで、
  食欲喚起（朱）と信頼（深緑）を両立させ、B2B サービスとしての落ち着きを出す。
- 朱は「CTA と重要な強調」だけに限定使用。使いどころを絞ることで CTA の視認性が上がる。

### タイポグラフィ

- 見出し：**Noto Serif JP**（600/700）— 明朝の縦線が「品書き」の世界観と合致し、テンプレート感を消す
- 本文・UI：**Noto Sans JP**（400/500/700）— 小さいサイズでも可読性が高い
- 数値・英字：`ui-monospace` 系を数値実績にのみ使用し、データの信頼感を演出
- サイズは `clamp()` による流体スケール。本文は 16px 未満にせず、モバイルでも 16〜17px を確保
- 行間は本文 1.9、見出し 1.35。日本語は行間を広めに取ることで可読性が大きく上がる

## 7. ファーストビューのキャッチコピー案

1. **一枚の品書きが、店の利益をつくる。**（採用）
   - 補足：味は変えずに、注文される順番を変える。飲食店専門のメニューデザインと集客支援。
2. おいしさは、伝わって初めて売上になる。
3. 「なんとなく安いもの」から、注文が始まっていませんか。
4. メニューは、店内でいちばん読まれる広告です。
5. デザインして終わり、にしません。数字が変わるまで。

採用案（1）を選んだ理由：**顧客の関心事（利益）と提供物（品書き）を一文で接続**しており、
サービス内容を知らない人でも業種と価値が同時に伝わるため。

## 8. 参考サイトを上回るための具体的な改善案

### 視認性
- 本文 17px／行間 1.9／1行あたり最大 38文字前後に制限（`max-inline-size: 38em` 相当）
- 全テキストのコントラスト比 4.5:1 以上、大見出しは 7:1 以上
- 情報は「見出しだけ読んでも意味が通る」構造。装飾見出しに情報を持たせない

### 信頼感
- 数値実績・料金・流れ・運営者情報をすべて公開（隠さないことが最大の信頼形成）
- 「必ず売上が上がる」といった断定を避け、条件付き・実測ベースの表現に統一
- 事業者情報、特商法に準ずる表記、プライバシーポリシーを整備

### 操作性
- モバイル固定CTAバー（スクロール開始後に出現、フッター到達で退避）
- タップ領域は最小 44×44px
- ハンバーガーメニューは `aria-expanded` ／ Esc キー ／ フォーカス移動に対応
- FAQ は `<details>/<summary>` によりネイティブ動作（JS 停止時も開閉可能）

### ブランド性
- 外部アイコンフォントを廃し、線幅を統一したオリジナル SVG アイコンに置換
- 罫線・余白・角丸（4px / 12px / 24px の3種のみ）・影（2段階のみ）を厳格に規定
- セクション見出しは「和文明朝＋英字ラベル」の型を全ページで統一

### コンバージョン率
- CTA を検討度別に3種（無料相談／料金を見る／事例を見る）用意し、離脱をフォームだけに賭けない
- フォームは必須項目を 5 つに絞り、任意項目と明確に分離
- 送信前に「営業電話はしません」「その場で契約を迫りません」と明記して心理的障壁を下げる
- 各サービス詳細ページの末尾に必ず CTA セクションを設置（回遊のどこからでも問い合わせ可能）

### 表示速度・Core Web Vitals
- JS は 1 ファイル・約 6KB、ライブラリ・フレームワークなし
- 画像はすべて SVG（ラスタ画像ゼロ）。`width`/`height`／`aspect-ratio` 指定で CLS を抑制
- Web フォントは `display=swap` ＋ `preconnect`、フォールバックに OS 標準の日本語フォントを指定
- スクロール演出は `IntersectionObserver` ＋ `transform`/`opacity` のみ（レイアウト再計算を発生させない）
- `prefers-reduced-motion: reduce` で全アニメーションを無効化

### SEO
- 1ページ1 `<h1>`、`h2` → `h3` の階層を崩さない
- 全ページに固有の `title` / `description` / `canonical` / OGP / Twitter Card
- 構造化データ：`ProfessionalService`（トップ）／`FAQPage`／`BreadcrumbList`／`Service`
- `sitemap.xml`・`robots.txt` を同梱

## 実装メモ

- 静的 HTML / CSS / JavaScript のみ。ビルド不要、そのままサーバーへアップロードで公開可能。
- 掲載している**実績数値・お客様の声・事例・事業者情報はサンプル**。
  HTML 内に `<!-- SAMPLE -->` コメントを付けているので、実データに差し替えて使用すること。
- お問い合わせフォームはフロントエンドの検証・完了表示までを実装。
  実運用時は `<form>` の `action` を送信先（メールフォームサービス／自前 API）に変更する。
